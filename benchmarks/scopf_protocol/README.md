# The protocol SCOPF instance set (18 instances, Tables `tab:gpu-scopf-pglib` and `tab:scopf-pglib-appendix`)

The second SCOPF instance set of the paper is generated by a fixed protocol from three PGLIB v23.07 networks,
`case500_goc`, `case588_sdet` and `case793_goc`. This directory holds the scripts that generated it, the records they
produced for the three networks, and `build_lists.py`, which rebuilds the contingency lists from the records. The
output of the protocol is `benchmarks/instances/scopf_pglib_contingencies.jl` (one list of 16 outages per network and
order) and `benchmarks/instances/scopf_pglib18.csv` (the 18 instances: 3 networks x 2 orders x K in {4, 8, 16}).

## The protocol (as stated in the manuscript, Section 5, paragraph "Two instance sets")

1. **Base case.** The base AC optimal power flow of the network (`julia/opf.jl`; Ipopt with MA27, at most 500
   iterations; every base solve of the three networks ended `LOCALLY_SOLVED`, `records/screens/*.meta.txt`).
2. **Screen.** Every branch outage is screened as in the reference benchmark: the post-contingency system with the
   base-case controls fixed is solved as **one penalized NCL subproblem** (multipliers 0, **penalty ρ = 1e8**, MadNLP
   with MA57 on the K2r system, tol 1e-8, **at most 200 iterations**), and the outage is **admitted when the scaled
   residual ‖r‖∞ < 1e-4**, whatever the termination status; **bridges are kept** (an outage that islands part of the
   network is screened like any other) (`julia/contingency_pool.jl`, `julia/screen_run2.jl`, `julia/screen_run3.jl`).
3. **Screening orders.** Order **A**: increasing PowerModels branch key. Order **B**: a seeded random order,
   `keys[randperm(MersenneTwister(69), n)]` over the n in-service branches (**seed 69**). Each list takes the first 16
   admitted outages of its screen, in screening order.
4. **Island rule.** An admitted outage is removed when it islands load that no generator of the island can serve:
   island load > 0 with no unit, or Σ Pmax < load, or Σ Pmin > load (active power only; `julia/bridges.jl`,
   `julia/islands.jl` → `records/islands.csv`).
5. **Single-contingency verification.** Every admitted outage is solved alone, as the K = 1 SCOPF problem of the
   harness model (`benchmarks/models/scopf_model.jl` with the `gpu.jl` SCOPF settings), by **Ipopt with MA57 at
   tol 1e-8, 10000 iterations, 3600 s** (`julia/k1_verify.jl` with `C3_WALL=3600 C3_MAXITER=10000`). The outage is
   removed when the solve ends `Infeasible_Problem_Detected`, or exhausts its budget with an unscaled constraint
   violation above 1e-3 ("presumed infeasible"); every other outcome keeps it.
6. **Drop and backfill.** Each removed outage is replaced, at the end of the list, by the next admitted outage of the
   same screen (screening order) that passes 4 and 5 (`build_lists.py`).
7. **Instances.** An instance with K contingencies takes the first K outages of a list, **K ∈ {4, 8, 16}**: 3 networks
   x 2 orders x 3 values of K = 18 instances. Each runs with the paper's SCOPF settings (`benchmarks/gpu.jl`:
   ε = 1e-8, τ_relax = 0, objective scaling 1e-4, 3000 iterations, 1800 s).

What the records show (`python3 build_lists.py lists`, `records/lists.md`): of the first 16 admitted outages of the six
screens, one, branch **657** of `case588_sdet` order B, was removed by the island rule (island of 2 buses, **52.85 MW**
of load, no unit) and replaced by branch **292**, the next admitted outage of that screen; the 96 list entries all pass
the island rule and all ended `Solve_Succeeded` at K = 1 (657's own K = 1 solve, which finished after the list was
built, ended `Maximum_Iterations_Exceeded` at 10000 iterations with an unscaled violation of 0.40). Budget of the recorded K = 1 solves: the order-B lists of `case588_sdet` and
`case793_goc` ran at the protocol budget (10000 iterations, 3600 s; `records/k1/k1_10000it_3600s/`); the lists of
`case500_goc` (A and B), `case588_sdet` A and `case793_goc` A were verified earlier in the pilot at 3000 iterations and
600 s (`records/k1/c3_3000it_600s/`), and every one of those 64 solves ended `Solve_Succeeded` within that budget (at
most 2380 iterations and 310 s). The longest protocol-budget solve took 3501 iterations (`case793_goc` B, branch 882).

Network eligibility (not part of the tables; records not ported): `case240_pserc` was excluded because the K = 1
verification failed (`Maximum_Iterations_Exceeded`) on 14 of its first 64 admitted outages (WO-69 Addendum C3, scopf-pool
`benchmarks/pilot/screen/out/c3_k1/`), and the pilot at K = 64 is why the ladder stops at K = 16 (scopf-pool
`benchmarks/results/pilot/`).

## The reference lists under the protocol

The first SCOPF instance set (Tables `tab:gpu-scopf` and `tab:scopf-config`, 23 instances) uses the contingency lists
published with the reference benchmark (`benchmarks/instances/scopf_contingencies.jl`) as published. Two checks connect
them to the protocol above; their records are in `records/reference_screens/` and `records/k1/reference/`, and
`python3 benchmarks/scopf_protocol/reference_check.py all --check` recomputes both tables from the records (seconds).

**Screens.** Every in-service branch of `case118`, `case300`, `case_ACTIVSg200` and `case_ACTIVSg500` was screened in
increasing branch key at penalty 1e8 with the protocol's admission rule (`julia/screen_run2.jl` in order `full`, on the
MATPOWER 7.0 files; WO-69 gate S0′). For the first three networks the admitted outages, in screening order, begin with
the published list:

| network | branches screened | bridges (admitted) | admitted | published list | first len(list) admitted = list |
|---|---|---|---|---|---|
| `case118` | 186 | 9 (0) | 156 | 156 | yes |
| `case300` | 411 | 89 (0) | 231 | 231 | yes |
| `case_ACTIVSg200` | 245 | 72 (11) | 179 | 145 | yes |
| `case_ACTIVSg500` | 597 | 254 (33) | 353 | 100 | no: first difference at entry 5; overlaps of the first 10/16/32/64/100: 6/12/26/56/91 |

The protocol therefore reproduces the published lists of `case118`, `case300` and `case_ACTIVSg200`, and does **not**
recover the list of `case_ACTIVSg500`. The networks `case1354pegase`, `case2869pegase` and `case_ACTIVSg2000` were
**not screened**. The island rule and drop-and-backfill were not applied to any published list: the 23-instance set uses
the lists exactly as published, and this section only checks them.

**Single-contingency verification.** Every listed outage that the 23 instances use was solved alone as the K = 1
SCOPF problem of the protocol's step 5 (harness model, Ipopt + MA57, tol 1e-8; `julia/k1_verify.jl`,
`records/k1/reference/summary.txt`). The lists of the four screened networks:

| list | entries verified | budget | Solve_Succeeded | other | max iterations | max solve time (s) |
|---|---|---|---|---|---|---|
| `case118` | 1–100 | 3000 iterations, 600 s (WO-69 C3) | 100 | 0 | 210 | 4.9 |
| `case300` (MATPOWER 7.0) | 1–100 | 10000 iterations, 3600 s | 100 | 0 | 2686 | 132.92 |
| `case300` (MATPOWER 8.1) | 1–100 | 10000 iterations, 3600 s | 100 | 0 | 2686 | 125.79 |
| `case_ACTIVSg200` | 1–100 | 10000 iterations, 3600 s | 100 | 0 | 380 | 9.45 |
| `case_ACTIVSg500` | 1–64 | 3000 iterations, 600 s (WO-69 C3) | 64 | 0 | 806 | 110.85 |
| `case_ACTIVSg500` | 65–100 | 10000 iterations, 3600 s | 36 | 0 | 674 | 65.61 |

Every one of the 500 solves ended `Solve_Succeeded`. The entries verified are the largest prefix any instance uses (K up
to 100). The two checks at 3000 iterations and 600 s pass the protocol budget a fortiori. `case300` was verified on both
case-file vintages because its K = 100 instance reads the MATPOWER 8.1 file and its K = 10 and K = 50 instances the 7.0
file; the 100 pairs of rows agree in every column but the time columns, so the two files build the same model.

The three published lists that were not screened were verified at the protocol budget as well (second run,
2026-11-12, 30 workers, 61 minutes); their outcomes are reported only and change no list:

| list | entries verified | Solve_Succeeded | other outcomes | max iterations | max solve time (s) |
|---|---|---|---|---|---|
| `case1354pegase` | 1–32 | 29 | 3 `Restoration_Failed` (entries 2, 10, 19: branches 27, 46, 92) | 1883 | 673.31 |
| `case2869pegase` | 1–16 | 15 | 1 `Restoration_Failed` (entry 15: branch 15) | 2522 | 2666.59 |
| `case_ACTIVSg2000` | 1–16 | 14 | 2 `Maximum_WallTime_Exceeded` at 3600 s (entries 4 and 11: branches 15 and 32) | 1659 | 3611.0 |

Every one of these six ended with a small unscaled constraint violation: about 1e-11 at the four `Restoration_Failed`
exits, and 1.1e-4 (branch 15) and 6.9e-7 (branch 32) at the two `case_ACTIVSg2000` wall-time exits. Under the protocol's
step 5 (remove an outage only on `Infeasible_Problem_Detected`, or on an exhausted budget with a violation above 1e-3)
none of the 64 would be removed, but six did not end `Solve_Succeeded`.

To rerun the protocol-budget checks (CPU, 30 workers: 4 minutes for the four screened networks, 61 minutes for the
other three lists):

```bash
D=benchmarks/out/scopf_data; benchmarks/instances/fetch_scopf_data.sh $D
R=benchmarks/out/scopf_protocol/k1_reference; mkdir -p $R
python3 benchmarks/scopf_protocol/reference_check.py jobs $D > $R/jobs.txt
C3_WALL=3600 C3_MAXITER=10000 C3_FIRSTPR=1 julia --project=benchmarks/envs/screen \
    benchmarks/scopf_protocol/julia/k1_verify.jl $R/jobs.txt $R       # start as many workers as you like on one jobs file
```

## Files

| path | contents |
|---|---|
| `julia/opf.jl`, `julia/contingency_pool.jl` | base AC-OPF and the screen subproblem (copies of the reference benchmark's screen, `contingency_problem` unchanged; `screen_candidates` screens a given candidate list) |
| `julia/bridges.jl` | in-service branches and bridges, with the islanded side of each bridge |
| `julia/screen_run2.jl` | the screen of the order-A lists and of `case500_goc` B: candidates in order until 16 (B) or 64 (A, the pilot's length) are admitted |
| `julia/screen_run3.jl`, `julia/null_probe_families.jl` | the screen of the order-B lists of `case588_sdet` and `case793_goc`: 300 candidates (run as four slices of 75 with `C2_SLICE=a:b`), also recording the raw residuals |
| `julia/islands.jl` | the island table (`records/islands.csv`) |
| `julia/k1_verify.jl` | the K = 1 verification (one row per outage; jobs from `build_lists.py jobs`) |
| `reference_check.py` | the reference lists under the protocol: `screens` (the S0′ comparison), `k1` (the K = 1 summary), `jobs` (the K = 1 jobs as run) |
| `build_lists.py` | `census` (screening census), `lists` (island rule, verification, drop and backfill; `--write`/`--check` the Julia list file), `jobs` (the K = 1 jobs still missing) |
| `records/screens/` | the six screens (`<network>_<order>.csv` + meta files: base status, ρ, candidates, case-file sha256) |
| `records/islands.csv` | the islands of every bridge of the three networks |
| `records/k1/<budget>/` | the 97 K = 1 rows (the 96 entries and the replaced outage 657) |
| `records/census.md`, `records/lists.md` | `build_lists.py census` and `build_lists.py lists` on the records |
| `records/reference_screens/` | the full screens of the four reference networks, the original comparison `S0p_compare.txt`, `SOURCE.txt` |
| `records/k1/reference/` | the K = 1 rows of the published lists (`k1_10000it_3600s/`, `c3_3000it_600s/`), `summary.txt`, `SOURCE.txt` |
| `records/SOURCE.txt` | provenance: every record's source path on scopf-pool and its sha256 |

All scripts run on the CPU in `benchmarks/envs/screen` (Julia 1.10.11; MadNCL from this checkout, MadNLP 0.10.1,
PowerModels 0.21.6, JuMP 1.32.1, Ipopt 1.16.0 and the licensed HSL_jll, which must be `Pkg.develop`ed from your own copy:
the Manifest records the path of ours).

## Rebuilding the lists

From the records (seconds; plain Python):

```bash
python3 benchmarks/scopf_protocol/build_lists.py lists --check=benchmarks/instances/scopf_pglib_contingencies.jl
python3 benchmarks/scopf_protocol/build_lists.py lists --write=benchmarks/instances/scopf_pglib_contingencies.jl
python3 benchmarks/scopf_protocol/build_lists.py census
```

From scratch (CPU; times measured on the campaign machine, 2 x Xeon Gold 6130):

```bash
D=benchmarks/out/scopf_pglib_data; benchmarks/instances/fetch_pglib_scopf_data.sh $D
E="julia --project=benchmarks/envs/screen"; J=benchmarks/scopf_protocol/julia; R=benchmarks/out/scopf_protocol
mkdir -p $R/screens $R/k1/k1_10000it_3600s
# screens (recorded elapsed, meta screen_s: 129 s, 78 s, 176 s, 326 s for 500 A, 500 B, 588 A, 793 A; the order-B
# screens of 588 and 793 ran as four slices of 75 candidates, 181-196 s and 218-228 s per slice)
$E $J/screen_run2.jl $D/pglib/pglib_opf_case500_goc.m  A 64 $R/screens/case500_goc_A  1e8
$E $J/screen_run2.jl $D/pglib/pglib_opf_case500_goc.m  B 16 $R/screens/case500_goc_B  1e8
$E $J/screen_run2.jl $D/pglib/pglib_opf_case588_sdet.m A 64 $R/screens/case588_sdet_A 1e8
$E $J/screen_run2.jl $D/pglib/pglib_opf_case793_goc.m  A 64 $R/screens/case793_goc_A  1e8
$E $J/screen_run3.jl $D/pglib/pglib_opf_case588_sdet.m B 0 300 $R/screens/case588_sdet_B   # 300 candidates, no stop rule
$E $J/screen_run3.jl $D/pglib/pglib_opf_case793_goc.m  B 0 300 $R/screens/case793_goc_B
# islands (9 s)
$E $J/islands.jl $R/islands.csv case500_goc=$D/pglib/pglib_opf_case500_goc.m \
    case588_sdet=$D/pglib/pglib_opf_case588_sdet.m case793_goc=$D/pglib/pglib_opf_case793_goc.m
# K = 1 verification at the protocol budget (recorded: 24-310 s per outage; any number of workers can share one jobs file)
python3 benchmarks/scopf_protocol/build_lists.py --records=$R jobs $D/pglib > $R/jobs.txt
C3_WALL=3600 C3_MAXITER=10000 C3_FIRSTPR=1 $E $J/k1_verify.jl $R/jobs.txt $R/k1_run
cp $R/k1_run/rows/*.csv $R/k1/k1_10000it_3600s/
python3 benchmarks/scopf_protocol/build_lists.py --records=$R lists   # repeat jobs/k1_verify while a check is pending
python3 benchmarks/scopf_protocol/build_lists.py --records=$R lists --check=benchmarks/instances/scopf_pglib_contingencies.jl
```

Checked in this checkout (CPU, 2026-11-11): `islands.jl` reproduces `records/islands.csv` byte for byte; one K = 1
check (`case588_sdet` A, branch 7) and the first two screened outages of `case588_sdet` B (`C2_SLICE=1:2`) reproduce
their records in every column but the time columns. The full screens and the 97 K = 1 checks were not rerun here.
