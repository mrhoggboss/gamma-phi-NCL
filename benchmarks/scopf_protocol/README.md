# The SCOPF instance protocol

All 41 SCOPF instances of Tables `tab:gpu-scopf` and `tab:scopf-appendix` (`benchmarks/instances/scopf41.csv`) are
generated by the protocol below (Algorithm 4 of the paper): 23 instances on seven reference networks (`case118`,
`case300`, `case_ACTIVSg200`, `case_ACTIVSg500`, `case1354pegase`, `case2869pegase`, `case_ACTIVSg2000`) and 18 on three
PGLIB networks (`case500_goc`, `case588_sdet`, `case793_goc`).
This directory holds the scripts that ran the protocol, the records they produced, and two builders that rebuild the
contingency lists from the records: `reference_networks.py` (`benchmarks/instances/scopf_contingencies.jl`) and
`build_lists.py` (`benchmarks/instances/scopf_pglib_contingencies.jl`).

## The protocol

1. **Base case.** The base AC optimal power flow of the network, solved by Ipopt with MA27 (at most 500 iterations;
   `julia/opf.jl`). Every recorded base solve ended `LOCALLY_SOLVED` (the screens' meta files).
2. **Screen.** Each branch outage is screened: the post-contingency system with the base-case controls fixed is solved
   as one penalized NCL subproblem (multipliers 0, penalty ρ = 1e8, MadNLP with MA57 on the K2r system, tol 1e-8, at most
   200 iterations), and the outage is admitted when the scaled residual ‖r‖∞ < 1e-4, whatever the termination status.
   Bridges are kept: an outage that islands part of the network is screened like any other (`julia/contingency_pool.jl`,
   `julia/screen.jl`, `julia/screen_raw.jl`).
3. **Screening order.** Order A: increasing PowerModels branch key. Order B: `keys[randperm(MersenneTwister(69), n)]`
   over the n in-service branches. The PGLIB networks are screened in both orders, one list of 16 outages per order. The
   reference networks are screened in order A, each list as long as the largest K of the network's instances (100 for
   `case118`, `case300`, `case_ACTIVSg200` and `case_ACTIVSg500`, 32 for `case1354pegase`, 16 for `case2869pegase` and
   `case_ACTIVSg2000`).
4. **Island rule.** An admitted outage is removed when it islands load that no generator of the island can serve:
   island load > 0 with no unit, or Σ Pmax < load, or Σ Pmin > load (active power only; `julia/bridges.jl`,
   `julia/islands.jl`).
5. **Single-contingency verification.** The admitted outages are solved alone, in screening order until the list is
   full, as the SCOPF problem with that one contingency (`benchmarks/models/scopf_model.jl` with the SCOPF settings of
   `benchmarks/gpu.jl`), by Ipopt with MA57 at tol 1e-8 within 10000 iterations and 3600 s (`julia/k1_verify.jl`). An
   outage is removed when the solve ends `Infeasible_Problem_Detected`, or exhausts its budget with an unscaled
   constraint violation above 1e-3; every other outcome keeps it.
6. **Drop and backfill.** Each removed outage is replaced, at the end of the list, by the next admitted outage of the
   same screen that passes steps 4 and 5.
7. **Instances.** An instance with K contingencies takes the first K outages of a list: K ∈ {4, 8, 16} on the PGLIB
   networks (3 networks × 2 orders × 3 values of K), the K values of `scopf41.csv` (4 to 100) on the reference networks.

What the records show. On the PGLIB networks one outage was removed: branch 657 of `case588_sdet` order B, by the
island rule (an island of 2 buses with 52.85 MW of load and no unit), replaced by branch 292, the next admitted outage
of that screen; the 96 list entries all ended `Solve_Succeeded` at K = 1. On the reference networks nothing was removed
and each list is the first n admitted outages of its screen; eight entries kept by step 5 did not end `Solve_Succeeded`
(`Restoration_Failed` at `case1354pegase` 6, 8, 46 and `case2869pegase` 15, with violations below 2e-11; the 3600 s wall
time at `case_ACTIVSg2000` 3, 8, 12, 15, with violations between 2.7e-5 and 3.1e-4). The K = 1 checks recorded at
3000 iterations and 600 s (`k1_3000it_600s/`: 64 rows of the PGLIB networks, 156 of `case118` and `case_ACTIVSg500`)
all ended `Solve_Succeeded` within that budget, so they pass the protocol budget: a solve that ends within 3000
iterations is the same solve under 10000.

## Files

| path | contents |
|---|---|
| `julia/opf.jl`, `julia/contingency_pool.jl` | the base AC-OPF and the screen subproblem; `screen_candidates` screens a given candidate list |
| `julia/bridges.jl` | in-service branches and bridges, with the islanded side of each bridge |
| `julia/screen.jl` | the screen: candidates in order until `kadmit` are admitted (or every branch, order `full`) |
| `julia/screen_raw.jl`, `julia/constraint_families.jl` | the screen that also records each outage's residual in the model's own units (the order-B screens of `case588_sdet` and `case793_goc`) |
| `julia/islands.jl` | the island tables |
| `julia/k1_verify.jl` | the single-contingency verification (one row per outage) |
| `build_lists.py` | the PGLIB networks: `lists` (`--write` / `--check` the Julia list file), `jobs` (the K = 1 checks still missing) |
| `reference_networks.py` | the reference networks: `lists` (`--write` / `--check`), `jobs` |
| `records/screens/`, `records/islands.csv`, `records/k1/<budget>/` | the PGLIB networks: six screens with their meta files, the islands, the K = 1 rows |
| `records/reference_networks/` | the reference networks: seven screens with their meta files, the islands, the K = 1 rows |

The scripts run on the CPU in `benchmarks/envs/screen` through `benchmarks/paper/julia.sh`. That environment loads a
licensed HSL from `benchmarks/envs/hsl/HSL_jll.jl` (gitignored): put or link your `HSL_jll.jl` there (the registry's
`HSL_jll` is a stub: check `filesize(HSL_jll.libhsl_path)` is megabytes) and instantiate the environment (another
`HSL_jll` version: `Pkg.develop` it into the environment instead).

## Rebuilding the lists from the records

```bash
python3 benchmarks/scopf_protocol/reference_networks.py lists --check
python3 benchmarks/scopf_protocol/build_lists.py lists --check=benchmarks/instances/scopf_pglib_contingencies.jl
```

`lists --write` (reference networks) and `lists --write=<file>` (PGLIB networks) write the files. Write the reference
file first: the PGLIB file copies its `case118` list, which the warm-up solve of `benchmarks/gpu.jl` uses.

## Regenerating the records

The PGLIB networks (screens of 1–6 minutes each; the order-B screens of 300 candidates 12–15 minutes; K = 1 checks of
at most an hour each, any number of workers sharing one jobs file):

```bash
D=benchmarks/out/scopf_data; benchmarks/instances/fetch_pglib_scopf_data.sh $D
J=benchmarks/scopf_protocol/julia; E="benchmarks/paper/julia.sh benchmarks/envs/screen"; R=benchmarks/out/scopf_protocol
mkdir -p $R/screens $R/k1/k1_10000it_3600s
$E $J/screen.jl $D/pglib/pglib_opf_case500_goc.m  A 64 $R/screens/case500_goc_A  1e8
$E $J/screen.jl $D/pglib/pglib_opf_case500_goc.m  B 16 $R/screens/case500_goc_B  1e8
$E $J/screen.jl $D/pglib/pglib_opf_case588_sdet.m A 64 $R/screens/case588_sdet_A 1e8
$E $J/screen.jl $D/pglib/pglib_opf_case793_goc.m  A 64 $R/screens/case793_goc_A  1e8
$E $J/screen_raw.jl $D/pglib/pglib_opf_case588_sdet.m B 0 300 $R/screens/case588_sdet_B   # SCREEN_SLICE=a:b splits it
$E $J/screen_raw.jl $D/pglib/pglib_opf_case793_goc.m  B 0 300 $R/screens/case793_goc_B
$E $J/islands.jl $R/islands.csv case500_goc=$D/pglib/pglib_opf_case500_goc.m \
    case588_sdet=$D/pglib/pglib_opf_case588_sdet.m case793_goc=$D/pglib/pglib_opf_case793_goc.m
python3 benchmarks/scopf_protocol/build_lists.py --records=$R jobs $D/pglib > $R/jobs.txt
$E $J/k1_verify.jl $R/jobs.txt $R/k1_run && cp $R/k1_run/rows/*.csv $R/k1/k1_10000it_3600s/
python3 benchmarks/scopf_protocol/build_lists.py --records=$R lists   # repeat jobs and k1_verify while a check is pending
```

The reference networks (the four full screens 1–12 minutes, the three stopped at 64 admitted 15–33 minutes):

```bash
D=benchmarks/out/scopf_data; benchmarks/instances/fetch_scopf_data.sh $D
J=benchmarks/scopf_protocol/julia; E="benchmarks/paper/julia.sh benchmarks/envs/screen"
R=benchmarks/out/scopf_protocol/reference_networks; mkdir -p $R/screens $R/k1/k1_10000it_3600s
for n in case118 case300 case_ACTIVSg200 case_ACTIVSg500; do
    $E $J/screen.jl $D/data_mp70/$n.m full Inf $R/screens/${n}_full_rho1e8 1e8
done
for n in case1354pegase case2869pegase case_ACTIVSg2000; do
    $E $J/screen.jl $D/data_mp70/$n.m A 64 $R/screens/${n}_A 1e8
done
$E $J/islands.jl $R/islands.csv $(for n in case118 case300 case_ACTIVSg200 case_ACTIVSg500 case1354pegase \
    case2869pegase case_ACTIVSg2000; do printf '%s=%s ' $n $D/data_mp70/$n.m; done)
python3 benchmarks/scopf_protocol/reference_networks.py --records=$R jobs $D > $R/jobs.txt
$E $J/k1_verify.jl $R/jobs.txt $R/k1_run && cp $R/k1_run/rows/*.csv $R/k1/k1_10000it_3600s/
python3 benchmarks/scopf_protocol/reference_networks.py --records=$R lists --check   # repeat jobs and k1_verify while pending
```

`k1_verify.jl` runs the protocol budget by default (`K1_MAXITER`, `K1_WALL` override it; `K1_FIRSTPR=0` drops the
column of the first iteration with an unscaled violation below 1e-6). Checked in this checkout: `islands.jl`
reproduces `records/islands.csv` byte for byte; the K = 1 check of `case588_sdet` A, branch 7, and the first two
screened outages of `case588_sdet` B (`SCREEN_SLICE=1:2`) reproduce their records in every column but the time columns.
